# Gatra-300M Data Recipe (2026-10-22)

> [!note] Konteks
> Desain *data* untuk Gatra langsung di ~300M, Indonesia-first. Induk: [[pretrain_llms/gatra/README|Gatra: Indonesia-first small LM]].
> Baseline arsitektur + budget: [[../efficient-llm-architecture-edge-under-500m-2026-10-20|Efficient LLM Architecture Edge <500M]] §5/§7.
> Validasi: [[gatra-repo-audit-2026-10-22|Gatra Repo Audit]] §1.3 (mix saat ini: CulturaX-id, FineWeb2-HQ ind_Latn, wiki-id, Aya-id ×2, Cendol, Kopi-news, newspapers-2018; **tanpa** English replay, code, math, sintetik; filter hanya `min_chars=80`; dedup hash eksak saja).

**Target:** ~3T token (±10k tok/param, rezim Sardana), repetition cap 4 epoch (Muennighoff) → butuh **≥750B token unik**.

> [!quote] Data-Constrained LMs, [arXiv:2305.16264](https://arxiv.org/abs/2305.16264)
> "training with up to 4 epochs of repeated data yields negligible changes to loss compared to having unique data. However, with more repetition, the value of adding compute eventually decays to zero."

**Kesimpulan di depan: sumber Indonesia saja TIDAK mencapai 750B unik.** Estimasi terbaik pasca-dedup lintas-sumber adalah **~100–150B token unik** (§1) → defisit ~5–7×. Resep ini menutupnya dengan English replay + code + math + sintetik terjemahan, dengan porsi Indonesia dipertahankan setinggi mungkin di dalam batas 4 epoch.

**Total unik pasca-dedup lintas-sumber: ~100–150B** (FineWeb-2 + MADLAD-id + CulturaX-id sebagai tiga pilar; sisanya <10B gabungan; overlap CC antar-pilar didedup MinHash §3 → ambil titik tengah **~130B** untuk perencanaan).

> Jawaban eksplisit: **tidak, sumber ID saja tidak mencapai 750B unik — shortfall ~600B (~80%).** Setiap resep jujur harus mengisi >80% budget dari non-ID atau sintetik.

## 2) Recommended mix (3T total, single-stage)

Prinsip: single-stage dari step-0 untuk ≤360M ("these smaller models benefited from a single-stage training approach with consistently high-quality data. We incorporated Stack-Edu from the start, alongside InfiMM-WebMath, FineMath, and Cosmopedia." — [SmolLM2](https://arxiv.org/abs/2502.02737)). Web EN 60/40 FineWeb-Edu/DCLM ("We adopted a 60% FineWeb-Edu and 40% DCLM ratio for web data" — sama).

| Komponen | Share | Token (dari 3T) | Unik tersedia | Epoch | Sumber |
|---|---:|---:|---:|---:|---|
| ID web (FW2 ind_Latn + MADLAD-id + CulturaX-id + KoPI + news + Leipzig + wiki) | 15% | 450B | ~130B | **3.5** ✅ | §1 #1–#8, HQ diutamakan |
| EN web (FineWeb-Edu / DCLM 60/40) | 52% | 1,560B | ~5.1T ("Combining these datasets yields 5.1T tokens of (English) text" — [SmolLM2](https://arxiv.org/abs/2502.02737)) | <1 ✅ | Replay anti-lupa; cf. Sailor2 100B replay/500B (20%) ([report](https://arxiv.org/abs/2502.12982)) |
| Code (Stack-Edu) | 15% | 450B | 125B ("a 125B token dataset of educational code filtered from The Stack v2" — [card](https://huggingface.co/datasets/HuggingFaceTB/stack-edu)) | 3.6 ✅ | Filter threshold 3/5 (Java 2) |
| Math (FineMath + InfiMM-WebMath) | 10% | 300B | ~54B + 40B ("up to 54B tokens" FineMath; "InfiMM-WebMath contains 40B text tokens" — [SmolLM2](https://arxiv.org/abs/2502.02737)) | 3.2 ✅ | Fokus deduksi step-by-step |
| Sintetik textbook (Cosmopedia-v2 + terjemahan-ID) | 7% | 210B | 30B EN ("Cosmopedia v2 … 30B tokens" — [SmolLM2](https://arxiv.org/abs/2502.02737)) + ~20B terjemahan-ID baru (§3.4) | 4.2 ⚠️ | Cap di 4.0 → tambah terjemahan bila perlu |
| Instruksi/paralel (Aya-id, Cendol) | 1% | 30B | ~1B | 15+ ❌ | **Pindah ke SFT**; di pretrain maks 0.3% atau hanya fase decay |

**Kenapa English 52% untuk model "Indonesia-first":** (a) defisit unik ID memaksa; (b) transfer lintas-bahasa nyata — "target language performance strongly correlated to the amount of in-language data seen during pretraining" dan bahkan korpus EN mengandung "hundreds of millions of foreign language tokens" ([Blevins et al.](https://aclanthology.org/2024.acl-long.796/)); (c) preseden produksi: Sailor2 CPT 400B SEA + 100B replay; Cendol menunjukkan "safety in pre-training in one language such as English is transferable to low-resource languages, such as Indonesian, even without RLHF" ([Cendol](https://aclanthology.org/2024.acl-long.796/)). 15% ID ≈ 3.5 epoch atas 130B unik: porsi ID tertinggi yang aman; naikkan hanya bila pasokan unik ID terbukti >130B.

**Kenapa code 15% + math 10% untuk chat ID:** SmolLM2 memakai "Stack-Edu 24%" dan "math 14% total" di decay 1.7B; untuk small single-stage, code+math dari awal terbukti membantu penalaran umum, bukan cuma coding ("including code data in pretraining enhances not only code-related capabilities but also improves natural language reasoning" — [SmolLM2 §3.4](https://arxiv.org/abs/2502.02737)). Tanpa keduanya, GSM8K-kelas-ID tidak akan bergerak (cf. floor kapasitas R1-140M di [[pretrain-best-practices-sub500m-2026-10-22|Best Practices]] §1f).

**Kenapa sintetik 7%:** Cosmo-1B (latih di 25B toks sintetik Mixtral) "performs better than TinyLlama 1.1B on ARC-easy, ARC-challenge, OpenBookQA, and MMLU" ([Cosmopedia](https://huggingface.co/datasets/HuggingFaceTB/cosmopedia)). Untuk Gatra, nilai terbesarnya adalah **terjemahan-ID dari Cosmopedia-v2** (preseden: Sailor2 "use NLLB 3.3B to translate high-quality English documents into local languages" — [report](https://arxiv.org/abs/2502.12982)) — textbook ID hampir tidak ada di web crawl.

## 3) Filtering / dedup / tokenizer pipeline

### 3.1 Quality filtering (pengganti `min_chars=80` saja)

| Stage | Metode | Bukti primer |
|---|---|---|
| LangID | FastText, threshold ≥0.5; buang bila prediksi ≠ `id` ("If this score is higher than 0.5, we classify the document … Otherwise … discard" — [CCNet](https://aclanthology.org/2020.lrec-1.494.pdf)); CulturaX memakai FastText re-prediksi karena "FastText has demonstrated state-of-the-art performance over benchmark datasets" ([CulturaX](https://arxiv.org/abs/2407.02518)) | Wajib untuk MADLAD/Leipzig/KoPI (risiko kontaminasi ms/jv) |
| Edu-quality | Klasifier gaya FineWeb-Edu: "trained on 450,000 pairs … generated by Llama3 … F1 score of 82% when converted to a binary classifier using a score threshold of 3" ([card](https://huggingface.co/HuggingFaceFW/fineweb-edu-classifier)); ambang `int_score >= 3`. Untuk ID: seed dari FineWeb-C ("58,185 total annotations, 122 languages" — [post](https://huggingface.co/blog/fineweb-c)) + anotasi Llama-3.1-70B-ID bila perlu (jalur FineMath memakai "Llama-3.1-70B-Instruct … scores content on a 3-point scale" — [SmolLM2](https://arxiv.org/abs/2502.02737)) | Ganti `min_chars` sebagai satu-satunya gate |
| Perplexity-gating | KenLM 5-gram Kneser-Ney latih di wiki-id; buang tercile terburuk ("we train a sentence piece tokenizer and a language model on data from the targeted domain. We use a 5-gram Kneser-Ney model as implemented in the KenLM library" — [CCNet](https://aclanthology.org/2020.lrec-1.494.pdf)) | Murah (CPU), tangkap boilerplate/SEO-spam yang lolos FastText |
| Toksisitas/URL | UT1 blacklist + metric cleaning (CulturaX pipeline) | Port langsung dari resep CulturaX |

### 3.2 Dedup: hash eksak → MinHash LSH

Repo hari ini hanya `blake2b` eksak (`prepare.doc_hash`, `data.write_corpus`). Pada skala 750B-unik-target dengan tiga pilar CC yang tumpang tindih, near-dedup wajib:

- Parameter FineWeb: "collect each document's 5-grams … computed MinHashes using 112 hash functions in total, split into 14 buckets of 8 hashes each — targeting documents that are at least 75% similar" + transitive clustering ([FineWeb](https://proceedings.neurips.cc/paper_files/paper/2024/file/370df50ccfdf8bde18f8f9c2d9151bda-Paper-Datasets_and_Benchmarks_Track.pdf)).
- Urutan: exact-hash dulu (murah, sudah ada) → MinHash LSH (datatrove) lintas-sumber → simpan `meta.json` dengan epoch-per-source untuk audit cap-4.

### 3.3 Tokenizer: BPE ID-first, fertility ≤1.5

- Target: BPE 32k ( hemat embedding di 300M) atau 49k (ikut SmolLM2). Korpus latih ikut resep SmolLM2 — "70% FineWeb-edu, 15% Cosmopedia-v2, 8% OpenWebMath, 5% StarCoderData, 2% StackOverflow" ([SmolLM2](https://arxiv.org/abs/2502.02737)) — **dengan porsi EN diganti ID** (70% → ID web HQ + terjemahan-ID, sisanya EN/code).
- Gate: fertility (tok/word) diukur di wiki-id + web-id + code; preseden ID: "Indonesian wiki 1.357, Indonesian web (CulturaX) 1.215" ([AksaraLLM-20B](https://huggingface.co/Ezekiel999/aksara-tokenizer-20b)). **Lolos bila ≤1.5 di kedua sampel ID** (vs byte-tokenizer repo hari ini yang ~6.5 tok/word — inflasi ~4–5×, cf. audit §2.1).
- Jangan latih tokenizer di atas Aya/Cendol terjemahan-MT saja (bias MT); dominan web+wiki asli.

### 3.4 Sintetik-ID (tutup celah textbook)

1. Ambil Cosmopedia-v2 slice skor-tinggi (~30B EN).
2. Terjemahkan ke ID dengan NLLB-3.3B (preseden Sailor2 §2) + filter balik: FastText-id ≥0.9, edu-classifier ≥3, MinHash-vs-web-ID (buang duplikat terjemahan dari artikel yang sudah ada).
3. Target ~20B toks unik-ID-sintetik → total unik sintetik ~50B → 210B/50B = 4.2 epoch; tambah volume terjemahan (FineWeb-Edu top-slice) hingga epoch ≤4.0.

## 4) Perubahan kode (`src/gatra/` + `configs/`)

| File | Sekarang | Ubah menjadi |
|---|---|---|
| `prepare.py` `SOURCES` | 9 sumber ID-only | Tambah: `madlad-id` (`allenai/MADLAD-400`, filter bahasa `id` clean), `leipzig-id` (file mentah Leipzig), `stack-edu` ([card](https://huggingface.co/datasets/HuggingFaceTB/stack-edu) — SWHID → unduh via Software Heritage S3), `finemath` + `infimm-webmath`, `cosmopedia-v2`, `fineweb-edu` + `dclm` (replay EN), `cosmo-id` (hasil terjemahan §3.4). Setiap entri baru catat `expected_unique_tokens` untuk audit cap-4 |
| `prepare.py` `write_jsonl` | `min_chars` satu-satunya gate | Tambah kolom skor opsional: `--edu-classifier` (path model, ambang ≥3), `--kenlm-id` (path model wiki-id, buang tercile-3), `--fasttext-lid` (tegakkan `id` ≥0.5); tulis `{"text", "scores"}` agar threshold bisa di-tune tanpa re-stream |
| `data.py` `write_corpus` | hash eksak + bobot fraksional + split hash | Tambah tahap MinHash LSH lintas-sumber pasca-exact (datatrove `MinHashDedup`), `SourceStats` catat `epochs = train_bytes/unique_bytes`, **gagalkan build bila ada sumber >4.0 epoch**; bobot mix pindah ke `configs/gatra-300m.toml` mengikuti tabel §2 |
| `data.py` bins | `uint8` memmap + `ByteTokenizer`-only (`load_bins` menolak non-byte) | Bins `uint16` (V≤65k) + `load_bins` terima `tokenizer: bpe`; `meta.json` simpan `tokenizer{name, vocab, fertility_id}` |
| `tokenizer.py` | `ByteTokenizer` V=256 | `BPETokenizer` (HuggingFace `tokenizers`, BPE byte-level) + `scripts/train_tokenizer_300m.py` (korpus §3.3) + `scripts/fertility_gate.py` (gagal bila >1.5 di wiki-id/web-id) |
| `configs/gatra-300m.toml` (baru) | — (10M: block 256, dropout 0.1, batch 8k) | `[data.mix]` = bobot §2; `block_size` 2048; `dropout 0.0`; batch ≥256k toks (akumulasi) → 1–2M saat DDP; `val_ratio` 0.02 (hemat unik); LR/schedule ikut best-practice (WSD, sweep 1–3e-3 via proxy μP) |
| `tests/` | `test_prepare`, `test_data` (hash/split) | Tambah: epoch-cap enforcement, MinHash determinism, fertility gate, mix-sum-to-1.0 |

Urutan kerja: tokenizer dulu (semua estimasi token bergantung padanya) → edu-classifier/KenLM → stream + MinHash → `gatra-build` → audit epoch → baru lock mix.

## 5) Fallback bila unik-ID < target

| Skenario | Respons |
|---|---|
| Unik ID terukur 80–130B (dugaan) | **Resep §2 jalan apa adanya** (ID 15% ≈ 3.5 epoch). Tidak perlu fallback. |
| Unik ID hanya 40–80B | Turunkan ID → 8–10% (340B/60B ≈ 5.7 epoch ❌ → potong budget total ke **2T**: ID 10% = 200B ≈ 3.3 epoch ✅; EN naik ke 58%). 2T/300M = 6.7k tok/param — masih dalam rezim Sardana ("no saturation point … even with additional data" s.d. 10k — [arXiv:2401.00453](https://arxiv.org/abs/2401.00448)). |
| Unik ID <40B | Mode CPT: pretrain EN/code/math penuh 3T, lalu continued-pretrain ID-heavy (Sailor2: "400B SEA-specific and 100B replay" dua tahap — [report](https://arxiv.org/abs/2502.12982)). Gatra-300M = model EN-kuat → adaptasi ID, bukan from-scratch ID. |
| Terjemahan-ID gagal (kualitas NLLB buruk) | Ganti porsi sintetik dengan Cosmopedia-v2 EN mentah (bukti Cosmo-1B > TinyLlama — [card](https://huggingface.co/datasets/HuggingFaceTB/cosmopedia)) + naikkan FineWeb-Edu; sintetik-ID jadi pekerjaan SFT, bukan pretrain. |
| MinHash terlalu agresif (unik menyusut >30%) | Longgarkan ke threshold ~85% + matikan transitive clustering; audit manual 200 sampel/duplikat-cluster sebelum lock. |

> Aturan keras di semua skenario: **tidak ada sumber yang melewati 4 epoch; budget yang dipotong lebih baik daripada epoch yang dijebol** (Muennighoff §0).
