Scope: concrete ~300M dense-transformer config for an Indonesia-first general-chat
model, edge deployment target (llama.cpp/GGUF CPU-first, Q4_K). Decides all 8
constrained knobs against primary sources only. Arithmetic below is recomputed
from the stated formula, not copied.

## 1. Recommended config (single table, all numbers computed)

Shared: decoder-only, pre-RMSNorm, SwiGLU, RoPE, GQA, tied embeddings,
`attention_bias=false`, MLP `bias=false`, dropout `0.0`, bf16 train → QAT int4.

| Knob | Value |
|---|---|
| Layers $L$ | **28** |
| $d_{model}$ | **960** |
| Q heads / KV heads | **15 / 3** (GQA group 5, $d_{head}=64$) |
| $d_{ff}$ (SwiGLU) | **2560** (2.67×) |
| Vocab $V$ (BPE, tied) | **32,768** |
| RoPE $\theta$ | **100,000** |
| Context (train block) | **4096** BPE tokens |
| Norm | pre-RMSNorm, eps 1e-6 **+ QK-norm ON** |
| z-loss / logit soft-cap | **OFF** (deferred, see §2.5) |
| Sliding window / sink tokens | **NO / NO** (full attention @4K) |
| **Params** | **299.9M** (emb 31.46M + body 268.48M + final norm 0.001M) |
| Embedding share | **10.5%** |
| KV cache (bf16) | **21.0 KiB/token → 84.0 MiB @4K / 168.0 MiB @8K** |
| Q4_K file (4.5 bpw) | **≈168.7 MB** |
| Decode ceiling @30 GB/s eff. BW | **≈117 tok/s @4K**, ≈87 tok/s @8K (upper bound; realistic 50–70%) |
| Prefill 4K | ≈2.46 TFLOP |

Param formula (tied): $N = Vd + L(2d^2 + 2d\,n_{kv}d_{head} + 3dd_{ff} + 2d + d + (Q{+}KV)d_{head}) + d$.
Per layer: attn 2,211,840 + FFN 7,372,800 + norms 4,032 = 9,588,672; ×28 = 268.48M;
+ emb 32,768×960 = 31.46M. QK-norm costs only (15+3)×64×28 ≈ 32k params (0.01%).

Rejected neighbours (same formula): V=49,152 → 315.6M / 14.9% emb / Q4_K 177.5 MB;
V=65,536 → 331.4M / 19.0% emb / 186.4 MB; 5 KV heads → 306.8M / 35 KiB/tok /
140 MiB @4K; FFN 4× (3840) → 403.1M (blows the budget outright).

## 2. Decision log (one quote + one citation per knob)

### 2.1 Depth: 28 layers (MobileLLM regime), not 15-wide (R1 regime)

MobileLLM's controlled sweep is the from-scratch evidence:

> [!quote] MobileLLM, [arXiv:2402.14905](https://arxiv.org/abs/2402.14905)
> "models with 30 or even 42 layers perform significantly better than those with 12 layers for transformer models sized around 125M"

and the family result: *"Leveraging deep and thin architectures, coupled with
embedding sharing and grouped-query attention mechanisms, we establish a strong
baseline network denoted as MobileLLM, which attains a remarkable 2.7%/4.3%
accuracy boost over preceding 125M/350M state-of-the-art models"* ([same](https://arxiv.org/abs/2402.14905)).
The R1 exception (15L/d1024/16Q-4KV/d_ff4096 @359.4M) is a **reasoning-distillation**
regime, not a from-scratch result: *"Knowledge distillation is applied with
Llama-3.1-8B-Instruct model as the teacher"* with 4.2T tokens, 128k vocab, and
*"We also incorporate QK-norm to mitigate training instabilities"* ([R1](https://arxiv.org/html/2509.24945v3)).
Gatra is from-scratch, Indonesia-first, general-chat, no ID teacher available →
default to the deep-thin regime (28L ≈ 30L rule at this width); probe the wide
regime only as A/B-1 (§3).

### 2.2 Vocab: 32,768 BPE, tied (not 49k / 64k / byte-256)

Three facts force this. First, the embedding tax at 300M is measured above:
10.5% (32k) vs 14.9% (49k) vs 19.0% (64k) — and the failure mode is public:

> [!quote] Google, [Gemma 3 270M blog](https://developers.googleblog.com/en/introducing-gemma-3-270m/)
> "170 million embedding parameters and 100 million transformer parameters, with a relatively large 256,000-token vocabulary"

i.e. 63% of a 270M model doing no reasoning. Second, tying is prescribed:

> [!quote] Weight tying, [arXiv:1608.05859](https://arxiv.org/abs/1608.05859)
> "we recommend tying the input embedding and this output embedding"

(Shipped-tied: SmolLM2-360M `"tie_word_embeddings": true`, [config](https://huggingface.co/HuggingFaceTB/SmolLM2-360M/raw/main/config.json);
Qwen3-0.6B ties below 8B, [config](https://huggingface.co/Qwen/Qwen3-0.6B/raw/main/config.json).)
Third, byte-256 is already measured 3.5–4× inflated on Gatra's own ID corpus
(`gatra-repo-audit-2026-10-22` §2.1: 1 byte ≈ 1 char on ASCII Indonesian vs
~3.5–4.5 chars/BPE-token), and FineWeb-2 gives the ID data story a citable base:

> [!quote] FineWeb-2, [arXiv:2506.20920](https://arxiv.org/abs/2506.20920)
> "produce FineWeb2, a new 20 terabyte (5 billion document) multilingual dataset"

covering 1000+ languages (incl. `ind_Latn`, the audit's planned source).
32k keeps the tax at ~10% while fitting Latin fertility; re-test 49k only as A/B-2.

### 2.3 GQA: 3 KV heads (5:1), not 5

> [!quote] GQA, [EMNLP 2023](https://aclanthology.org/2023.emnlp-main.298/)
> "uptrained GQA achieves quality close to multi-head attention with comparable speed to MQA"

at *"5% of original pre-training compute"* ([same](https://aclanthology.org/2023.emnlp-main.298/)).
Shipped ratios bound the choice: Qwen2.5-0.5B 14Q/2KV, SmolLM2-360M 15Q/5KV
(`"num_key_value_heads": 5`, [config](https://huggingface.co/HuggingFaceTB/SmolLM2-360M/raw/main/config.json)),
MiniCPM4-0.5B 16Q/2KV ([config](https://huggingface.co/openbmb/MiniCPM4-0.5B/raw/main/config.json)).
At $d{=}960$, 3 KV heads give 21 KiB/tok (84 MiB @4K — half the weight file);
5 KV heads cost +6.9M params and 35 KiB/tok (140 MiB @4K) for an unablated quality
delta at ≤500M. Take 3; A/B-3 tests 5.

### 2.4 FFN: SwiGLU 2.67× (2560), not 4×

> [!quote] GLU variants, [arXiv:2002.05202](https://arxiv.org/abs/2002.05202)
> "for the GLU-variant-based FFN layers, which have three weight matrices instead of two, we reduce the hidden layer to $d_{ff}=2048$" (from 3072 at $d{=}768$)

i.e. 2/3·4$d$ = 2.67$d$ — exact in SmolLM2-360M (`"intermediate_size": 2560` at
`"hidden_size": 960`, [config](https://huggingface.co/HuggingFaceTB/SmolLM2-360M/raw/main/config.json)).
The 4× counter-examples are real but budget-breaking here: MiniCPM4-0.5B ships
`"intermediate_size": 4096` at hidden 1024 ([config](https://huggingface.co/openbmb/MiniCPM4-0.5B/raw/main/config.json))
and R1-360M uses 4096/1024 ([R1](https://arxiv.org/html/2509.24945v3)) — at Gatra-300M,
4× alone adds ~103M params (→403M). Default 2.67×; 4× is not a knob, it is a
different budget.

### 2.5 Stability kit: QK-norm ON, z-loss OFF, soft-cap OFF

> [!quote] Qwen3 report, [arXiv:2505.09388](https://arxiv.org/html/2505.09388)
> "we remove QKV-bias used in Qwen2 and introduce QK-Norm to ensure stable training for Qwen3"

plus R1: *"We also incorporate QK-norm to mitigate training instabilities in the
self-attention block"* ([R1](https://arxiv.org/html/2509.24945v3)). Two independent
sub-1B families ship it → default ON (≈32k params, §1).
z-loss and logit soft-cap (Gemma 2: *"50.0 for self-attention, 30.0 for the final
layer"*, [report](https://arxiv.org/html/2408.00118)) stay OFF by default because
neither appears in the SmolLM2-360M nor Qwen3-0.6B configs linked above and no
controlled ≤500M ablation exists for any of the three (validation note §1(e)) —
enable on instability, do not pay upfront complexity.

### 2.6 RoPE θ=100k, context 4096

SmolLM2-360M ships `"rope_theta": 100000` at 8K context
([config](https://huggingface.co/HuggingFaceTB/SmolLM2-360M/raw/main/config.json));
Qwen3-0.6B ships θ=1e6 for 32K ([config](https://huggingface.co/Qwen/Qwen3-0.6B/raw/main/config.json)).
θ=100k therefore covers the 4K chat target with headroom (and matches the
§7.1-350M blueprint family), while Qwen3 shows the scaling direction if context
ever extends to 32K. No θ ablation exists at ≤500M (both SmolLM2 sizes share
100k) — treat as safe default, not tuned optimum.

### 2.7 Sliding window + sinks: NO

> [!quote] StreamingLLM, [arXiv:2309.17453](https://arxiv.org/abs/2309.17453)
> "keeping the KV of initial tokens will largely recover the performance of window attention"

with *"just 4 initial tokens sufficing"* ([same](https://arxiv.org/abs/2309.17453))
— but validated on ≥2.9B models only, and windowing discards exact recall outside
the window. At 4K the full-attention KV is 84 MiB (§1), smaller than the 168 MB
weight file; Qwen3-0.6B likewise ships `"use_sliding_window": false`
([config](https://huggingface.co/Qwen/Qwen3-0.6B/raw/main/config.json)). Full
attention, no sinks. Revisit only if the product demands ≥8K (KV 168 MiB).

### 2.8 Tying / biases / dropout (locked, no A/B)

Tying ON (§2.2 quote). Biases OFF everywhere (Qwen3 lineage: *"we remove
QKV-bias used in Qwen2"*, [report](https://arxiv.org/html/2505.09388); SmolLM2-360M
`"attention_bias": false, "attention_dropout": 0.0`, [config](https://huggingface.co/HuggingFaceTB/SmolLM2-360M/raw/main/config.json)).
Dropout 0.0 for pretraining (same config line; audit flags the current 0.1 as a
hygiene miss). RMSNorm throughout:

> [!quote] RMSNorm, [arXiv:1910.07467](https://arxiv.org/abs/1910.07467)
> "RMSNorm is computationally simpler and thus more efficient than LayerNorm"

## 3. Ablation plan (max 3, same data, 50–100B tokens each, ID-chat + GSM8K-ID gates)

- **A/B-1 — depth regime (the R1 question):** deep default (28L/d960/15Q-3KV/2.67×,
  299.9M) vs wide R1-style probe (17L/d1024/16Q-4KV/d_ff4096/V32k ≈ 292M).
  Decides whether the 15L-wide + 4×-FFN recipe transfers to from-scratch
  Indonesian chat without an 8B teacher. If wide wins only on math, keep deep
  base + reasoning-SFT later.
- **A/B-2 — vocab 32k vs 49k:** same 28L body; V=32,768 (299.9M, 10.5% emb) vs
  V=49,152 (315.6M, 14.9% emb). Gate on ID fertility (chars/token on the audit
  corpora) + val ppl + GSM8K-ID. Promote 49k only if fertility gain exceeds the
  ~9 MB Q4_K + quality cost.
- **A/B-3 — GQA 3 vs 5 KV heads:** same 28L/V32k; 3KV (84 MiB @4K) vs 5KV
  (306.8M, 140 MiB @4K). Gate on quality delta vs KV/latency cost on-device
  (llama.cpp tok/s @4K). Fallback: ship 3, uptrain to 5 later (5%-compute
  conversion per §2.3 quote).

## 4. Code-change checklist (`src/gatra/model.py` + `config.py`)

`config.py` — `ModelConfig`:
- [ ] `n_layer` 4 → **28**, `n_embd` 128 → **960**, `n_head` 4 → **15**
  (keep name; semantics = Q heads).
- [ ] **Add** `n_kv_heads: int = 3` (new field; `__post_init__` asserts
  `n_embd % n_head == 0`, `n_head % n_kv_heads == 0`, head_dim even).
- [ ] `n_ff`: set explicit **2560** (current auto-formula already yields
  2.67×⌈64⌉ = 2560 @960 — keep formula, pin value in the 300M toml).
- [ ] `vocab_size` 256 → **32768**; `block_size` 128 → **4096**;
  `dropout` → **0.0**; `rope_base` 10_000 → **100_000**.
- [ ] **Add** `use_qk_norm: bool = True`; **add** `z_loss_coef: float = 0.0`

- [ ] New `configs/gatra-300m.toml` with the §1 table; keep `tie` (already
  hardcoded in `Gatra.__init__`).

`model.py` — MHA → GQA (the ~20-line change the audit scoped):

- [ ] `RotaryEmbedding`: `max_seq` 256 → 4096 buffer (4096×64 fp32 ≈ 1 MB —
  no action beyond block_size); no logic change.
- [ ] `Block`/`Gatra`/`generate`: unchanged (residual + dropout path already
  correct; `generate` already truncates `idx[:, -block_size:]`).
- [ ] `param_count()` gate: assert ≈299.9M after the change.
- [ ] Out-of-scope-but-blocking companions (same PR, different files):
  `tokenizer.py` ByteTokenizer → BPE-32k trained on the ID build + fertility
